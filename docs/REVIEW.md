## Повторение обычных проверок

Из корня репозитория:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r lab2/requirements-validation.txt -r lab3/requirements.txt
.venv/bin/python lab2/validate.py
.venv/bin/python lab3/manage.py check
.venv/bin/python lab3/manage.py test tests --settings=app.config.test_settings
.venv/bin/python tools/check_docs.py
git diff --check
```

Для SQL требуется отдельная пустая PostgreSQL:

```sh
createdb commandx_lab1
psql -v ON_ERROR_STOP=1 -d commandx_lab1 -f lab1/database/schema.sql
.venv/bin/python tools/check_schema.py --database-url postgresql:///commandx_lab1
```

Проверка схемы read-only и не меняет данные. Создание схемы выполняет предыдущая команда; её нельзя запускать в рабочей БД. [Машинный снимок моделей](../lab1/database/model-snapshot.json) содержит структуру, без записей и секретов.

## Повторение сверки с исходным проектом

Опционально, когда актуальный CommandX доступен локально. Укажите собственный путь:

```sh
COMMANDX_SOURCE=/path/to/pic_project
.venv/bin/python -m pip install -r "$COMMANDX_SOURCE/backend/requirements.txt"
.venv/bin/python tools/check_reference.py --source "$COMMANDX_SOURCE"
```

Скрипт сначала проверяет SHA-256, затем конфигурирует Django самостоятельно, не загружая настройки и `.env` источника. Применяет миграции только к SQLite в памяти. Проверяет auth, CRUD, владельца, административную роль, сохранение SSH-секрета, ответы команд/метрик, доступ, demo-баланс и AI без ключа. SSH подменён; реальные ключи не используются. Если файлы исходника изменились, проверка останавливается: сначала требуется содержательная повторная сверка, затем обновление manifest.
