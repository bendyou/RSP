# Инструкции для агента

Этот репозиторий содержит лабораторные по дисциплине «Разработка серверных приложений» для **CommandX — панели управления собственными серверами по SSH**.

## Прежде чем менять работу

1. Прочитай этот файл, `docs/PROJECT_CONTEXT.md`, корневой `ARCHITECTURE.md` и README нужной лабораторной.
2. Получи исходное задание следующей лабораторной. Если его нет, запроси текст задания; не придумывай требования по её номеру.
3. Проверь `git status`, текущую ветку и пользовательские изменения. Не откатывай их.
4. Сверь затрагиваемые модели и маршруты с актуальным исходным проектом. На компьютере владельца источник: `/Users/vladmambetov/Documents/study/3.1/pic_project`. На другой машине используй `COMMANDX_SOURCE` или попроси путь. У источника есть незакоммиченные изменения: один только Git HEAD не описывает его состояние. Контрольные суммы файлов зафиксированы в `docs/source-manifest.json`.

## Неизменяемая основа

- Один сквозной проект: CommandX. Не возвращай «Мою библиотеку», коллекции книг или вымышленную систему инцидентов и агентов мониторинга.
- Python, Django 5.2, Django REST Framework, SimpleJWT; React/TypeScript/Vite в исходном frontend. Замена backend на FastAPI не согласована.
- Существующие маршруты начинаются с `/api/`, имеют завершающий `/`. Не добавляй `/api/v1` и не переименовывай маршруты без явного задания и описания совместимости.
- Регистрация использует `username`, `email`, `password`, `password_confirm`; вход — `username` и `password`; токены — `access` и `refresh`.
- Роли: пользователь и администратор (`is_staff`). Администратор не получает автоматически доступ к чужим SSH-серверам: queryset ограничен `created_by`.
- Сущности: стандартный `auth.User`, `UserProfile`, `Server`, `ServerMetric`, `Transaction`, legacy `AllocatedServer`. Не добавляй таблицы только ради количества сущностей.
- `Server.is_active` управляет доступом в панели, не питанием ОС. Метрики собираются по запросу через SSH. Платёжный провайдер не подключён. AI опционален.
- `lab3` — каркас и health-check. Полноценный backend исходного проекта не скопирован и не считается реализованным в лабораторных.

## Следующие лабораторные

Лабораторная №4 **не выполнялась**. Не создавай `lab4`, её код, модели или миграции без отдельного запроса пользователя. Когда такой запрос появится, сначала прочитай реальное задание и документы выше. Продолжай последнюю завершённую работу, сохраняя структуру `controller → service → repository`, а конфигурацию — отдельно.

Модели добавляй только тогда, когда это требуется заданием. Миграции сохраняй в Git, проверяй на отдельной пустой БД. Не применяй учебный `lab1/database/schema.sql` к существующей БД: это снимок DDL для анализа, а не миграция. `auth_user.id` в исходнике — INTEGER, собственные сущности — BIGINT; смена стандартного User требует отдельного решения.

Любое расхождение учебного контракта с исходником явно документируй. Проверяй права владельца, невалидные запросы и отсутствие секретов в ответах. Обновляй OpenAPI, таблицу маршрутов, ERD и инструкцию запуска при изменении соответствующего поведения. Канонические файлы: отчёт №1 и диаграммы в `lab1`, спецификация в `lab2/openapi.yaml`; корневые копии `ARCHITECTURE.md` и `openapi.yaml` поддерживай согласованными.

## Проверки и Git

Команды проверки находятся в README лабораторных и `docs/REVIEW.md`. Не заявляй об успешном тесте без запуска. Проверки не должны использовать рабочую БД, SSH-хосты, реальные платежи или AI-запросы.

`main` содержит все завершённые работы; `lab1`, `lab2`, `lab3` — последовательные состояния для сдачи. Новую работу начинай от актуального `main`, создавай ветку по её номеру и сохраняй предыдущие ветки. Не переписывай историю и не выполняй force-push без отдельного разрешения. Публикуй только изменения, входящие в запрос пользователя. Не добавляй GitHub-комментарии и `Co-authored-by`. Не добавляй комментарии в новый код. Используй краткие сообщения коммитов без тела и без атрибуции агента.

Не публикуй `.env`, SSH-ключи, пароли, пользовательские данные, дампы БД, виртуальные окружения, архивы и случайные снимки экрана. Примеры должны содержать только вымышленные данные. Исходный `pic_project` используй для чтения, если отдельно не поручено его изменение.
